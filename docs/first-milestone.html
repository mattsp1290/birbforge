Outcome#

An authenticated owner can begin a goal conversation on a phone, continue it in a Mac browser, and resolve the same pending input through either conversation or inbox. Both clients converge on authoritative state after reconnect.

Use Birbcrew's human-input request, resolved by ID and version through an authenticated Birbforge action. Generated local test credentials suffice for this isolated proof. Production identity is a later deployment gate.

Scope and dependencies#

Use the proven Birbcrew AG-UI contract and fixtures. Validate Expo and React Native Web against the selected SDKs before expanding the interface. Share domain state and action handlers. Use platform-specific presentation where a browser-only CopilotKit component cannot run natively. Do not substitute an embedded browser demonstration for the required native phone journey.

Build one real conversation and one durable input decision. Keep PRs, cloud dispatch and notifications as explicit later milestones. The decision fixture does not grant merge authority. Reuse CopilotKit OSS where it reduces work. Intelligence is excluded. A2UI is unnecessary for this acceptance journey.

Consume Beans-backed context through the agreed boundary. Beans owns authored work records and shared notes. Avoid creating another editable work or notes store. Use synthetic records in a disposable Beans hub for the first UI proof.
