# Private phone access workflow

## Ground

The Mac return handoff `birbforge-h-kpde` establishes browser checks at
9fa6bc419e7eb0ee7602246d26b85509074ca109 and a concrete phone access failure.
No native app ran. The user authorized work on this bounded route and selected
existing HTTPS infrastructure. No DNS, network, account, OS trust, or firewall
change has been performed in this implementation session.

The existing handler authenticates API calls, forwards each principal's own
producer credential, and streams AG-UI without altering decisions. Birbcrew
remains the durable authority. Transport access must reuse that handler.

## Current data shape

The optional proxy backend accepts only a port and one canonical external HTTPS
origin. Both application listeners bind to 127.0.0.1. Proxy requests must arrive
from that exact loopback source. Configurable bind addresses, source lists, and
forwarded-header trust are unsupported. Credentials remain in the private runtime
configuration. The existing HTTP loopback authority remains available.

The selected path is an existing private HTTPS proxy, an existing enrolled
verification peer, and its already authorized SSH connection into runtime
loopback. This design is covered by the [fresh fix review](private-fix-review.json),
which is the first independent review of the reduced SSH-bridge shape. It is
not a merge or activation approval. Its activation findings require source,
ingress-interface, direct-peer and LAN-denial checks before the bridge is used.
Those live checks remain NOT VERIFIED.

## Design history

1. The [first review](private-design-review.json) compared app-owned TLS and a
   new forwarding proxy. It predates the owner's existing-infrastructure evidence
   and does not approve the final design.
2. The [revised review](proxy-design-review.json) evaluated a configurable CGNAT
   backend for the existing private HTTPS proxy. It is also historical.
3. The [code review](private-code-review.json) identified a possible plaintext
   LAN hop in that broad configuration. Rather than adding exceptions, the
   implementation deleted bind/source options. Host inspection also did not
   establish a local NetBird interface. Private interface details are intentionally
   absent from public evidence; this is not proof of a working overlay route.
4. The implementation owner observed the TLS fixture's SNI/Host coupling during
   development. The corrected fixture now uses normal chain validation and Node's
   hostname checker against the origin. The reviewer did not run that fixture.
5. The fix review challenged bridge reachability and scan reproducibility. The
   activation procedure now requires direct-port denial and observed ingress.
   The scan and its synthetic-key probe are generated by the committed script
   and invoked from `scripts/verify`, rather than an undocumented manual step.

## Throughput checkpoint and principles

Use the real pinned producer behind a disposable TLS proxy. Its test CA is
trusted only by the fixture client, never installed in OS or device trust.
Observe an official SDK subscriber receive authoritative final state and a
single winning raced decision. Keep fixture and live route evidence separate.

Model the Domain keeps the two listener policies distinct. Boundary Discipline
keeps source, Host, Origin, config ownership and command checks at the boundary.
Laziness Protocol deleted unnecessary trust configuration. Prove It Works keeps
live bridge isolation and native/Mac acceptance open despite passing local tests.
